## 验证场景

1. 三个账号初始倍率 0.3 / 0.5 / 0.8，抑制阈值 1。首次执行注册专属成本标记，正常账号保持可调度。
2. 将前两个账号提高到 1 / 3：抑制非兜底账号，新请求和粘性会话均不得绕过。兜底即使倍率升至 5 或成本探测失败，仍保留基础健康条件下的使用资格。
3. 将一个被抑制账号骤降至 0.1：解除 Monitor 成本标记，降低优先级，同一个完整历史会话从兜底切回；稳态不重复写入。
4. 管理员停用账号：成本恢复不得改变手动开关。普通账号编辑不得用陈旧快照覆盖 Monitor 抑制标记。
5. WebSocket 下一轮重新检查成本门。连接不能直接换账号；被阻止时要求重连并重放完整上下文。仅依赖 previous_response_id 的服务端状态续链不做隐式迁移。
6. 251 条用量跨多页，其中同一会话 A→B→A；第二页超时，第一页面游标和通知仍已持久化。重试从断点续传，ntfy / Telegram 各两条切换通知，不重复入队。
7. 旧页不得回退会话状态；新会话同一批次内的连续切换全部识别。首次启用单独建立当前基线（包括升级前遗留的会话状态），不补发历史切换。Worker 取消时先回滚未完成页，再释放租约。
8. 聚合滞后两小时但历史覆盖完整：指标保留为历史数据，当前健康未知。分组倍率 0.3 与账号倍率 3 必须分开展示；其他目标/分组的账号不得混入。
9. 已删除账号/模型的旧绑定保持只读，保存普通参数或停用策略不再返回 422；尝试修改模型绑定仍返回暂停状态。
